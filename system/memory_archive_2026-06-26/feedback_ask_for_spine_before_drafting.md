When prepping a VP-altitude communication structure for James — talk-track spine, install beats, narrative arc, install order for a sponsor consult — **ask James for his intended structure FIRST** instead of confidently drafting one in a generic frame. James usually has a specific structure in mind that's more native to the actual technical work and how he wants to present it.

**Why:** 2026-05-02b session — I drafted a generic 4-beat Anticipation spine in thesis → proof → portability → next framing, iterated 2-3 times polishing it. James then said: *"I think the main beats should be: 1) WAU gains in US CAN from much better representation and leveraging this in retrieval, ranking, and blending. 2) Why this works is because of UIC uniquely captures Pinterest, where each pin means something different for a different user. 3) This is immediately portable via CLR in the base training to Notif. 4) Next steps is Anticipation, where I'll show the LLM-based pUIC."* His structure was sharper, more technically specific, and Pinterest-native. I had to replace mine wholesale across multiple files.

**How to apply:** Before drafting a multi-beat spine / install order / narrative arc for James to use in stakeholder communication, ask: "Do you have a structure in mind for how the beats should land, or want me to propose one?" If he proposes, build on it. If he doesn't, propose ONE option with explicit "is this the right shape, or do you have a different ordering?" — don't iterate on yours through 2-3 polishes before checking. The cost of one clarifying question is much lower than the cost of wholesale-replacing a polished draft.
