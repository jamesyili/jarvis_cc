When James is asking for pure technical thinking-partner mode on system design, model architecture, or build sequencing, drop the sponsor-narrative framing entirely. Don't reach for "which sponsor does this serve" / "how does this read to Faisal/Rajat/Andrew" / "this maps to thread X" as a default analytical lens.

**Why:** 2026-05-11 session — Reflex folder thinking-partner. James asked for technical brainstorming on Pinkerton + VLM + Anticipation. Leo's first three response cycles kept defaulting to sponsor mapping (which option serves Faisal, what's the calibration-window leverage, etc.). James pushed back explicitly twice: *"this is just a bunch of docs"* and *"I'm not managing up here. I'm genuinely trying to think through technical design."* The sponsor framing wasn't wrong-but-misweighted; it was actively crowding out the actual technical thinking he wanted.

**How to apply:**
- **Signals to drop sponsor framing:** *"think through technical design"*, *"what are we building"*, *"I'm not managing up"*, *"stop with the [sponsor/narrative/framing/political] stuff"*, *"deeper on the technical"*, or any direct technical-design request (system architecture, model design, data shape, build sequencing).
- **Once dropped, stay dropped for the rest of that session.** Don't sneak it back in two turns later under a different label. If sponsor connections genuinely matter for a decision, note them at end as "one possible angle" — never as the analytical anchor.
- **Sponsor framing is appropriate when:** James is prepping for a meeting, drafting stakeholder comms, reviewing his narrative, asking about visibility / calibration / scope. Default ON for those. Default OFF for pure technical thinking partner.
- This is NOT the same as "never mention stakeholders" — it's "don't make sponsor-leverage the organizing frame of technical analysis."
