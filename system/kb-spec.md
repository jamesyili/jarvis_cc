# LLM Knowledge Base System — Implementation Spec

## Overview
A two-tier knowledge base (raw sources + compiled wiki) organized by domain (hard skills / soft skills), backed by Obsidian for graph navigation. Raw content is ingested from curated sources and migrated from the existing `learning/` directory. A compiler powered by Claude synthesizes raw content into cross-cutting concept articles in the wiki layer. Cron-driven scrapers keep raw content fresh. The whole system lives at `/home/james/src/leo/kb/`.

## Rules
- Everything in `raw/` compiles to wiki EXCEPT `raw/do_not_index_sources/`
- `raw/do_not_index_sources/` is archive — original long-form material for reference only
- Long-form content gets distilled before entering `raw/{source-slug}/`
- Short-form content goes directly to `raw/{source-slug}/`
- Compiler only reads from `raw/` (excluding do_not_index_sources/) to build wiki

## Data Model

### Raw Article (existing format, preserved as-is during migration)
```markdown
# {Title}

**Source:** {URL}
**Ingested:** {YYYY-MM-DD}
**Tags:** {comma-separated tags}

---

{content}
```

### Wiki Article (generated by compiler)
```markdown
---
concept: {Concept Name}
tags: [{tag1}, {tag2}, ...]
sources: [{relative path to raw source 1}, {relative path to raw source 2}, ...]
last_compiled: {YYYY-MM-DD}
related: [{related-concept-1}, {related-concept-2}, ...]
---

# {Concept Name}

{Synthesized content — definitions, key ideas, practical applications, nuances.
 Written as a standalone reference article. Uses [[wikilinks]] for cross-references.}

## Sources
- [[hard/raw/aman-ai/two-tower-models.md]]
- [[hard/raw/eugene-yan/retrieval.md]]
```

### Raw Index (`_index.md`) format
```markdown
# Hard Skills — Raw Content Index

> Auto-generated. {N} articles across {M} sources. Last updated: {YYYY-MM-DD}

| Title | Source | Tags | Path | Wiki Concepts |
|-------|--------|------|------|---------------|
| Two-Tower Models | aman-ai | retrieval, embeddings | [[hard/raw/aman-ai/two-tower-models.md]] | [[hard/wiki/two-tower-models.md|Two-Tower Models]] |
```

### Wiki Index (`wiki/_index.md`) format
```markdown
# Hard Skills — Wiki Index

> Auto-generated. {N} concept articles. Last updated: {YYYY-MM-DD}

| Concept | Description | Sources | Related |
|---------|-------------|---------|---------|
```

### T-5: Wiki compiler
Core intelligence. Scans raw content, identifies cross-cutting concepts, produces wiki articles.

**Three phases:**
1. **Scan** — LLM reads raw catalog, identifies concepts + source mappings → JSON
2. **Plan** — Generates `_plan.md` for human review before compilation
3. **Compile** — For each concept, reads source articles, synthesizes wiki article

**Acceptance criteria:**
- [ ] `compile_wiki.py scan --domain hard` returns valid concept JSON
- [ ] `compile_wiki.py plan --domain hard` generates reviewable plan
- [ ] `compile_wiki.py compile --domain hard --all` compiles all concepts
- [ ] `compile_wiki.py incremental --domain hard` detects new/modified raw files, recompiles affected concepts
- [ ] Generated articles follow the wiki article schema
- [ ] All cross-references use `[[wikilinks]]`
- [ ] Tracks state in `.compile_state.json`

## Skill Surface

Eight KB skills, hybrid architecture (Python scripts for deterministic work, Claude Code skills for LLM judgment):

| Skill | Type | Description |
|-------|------|-------------|
| `/kb-status` | Skill (wraps scripts) | Dashboard: article counts, scout times, index age, wiki state |
| `/kb-ingest` | Skill (wraps `ingest.py`) | Ingest URLs, PDFs, notes → routes to hard/soft, rebuilds indexes |
| `/kb-scout` | Skill (wraps `scout.py`) | Trigger RSS scout run for all or single source |
| `/kb-lint` | Hybrid (script + skill) | `kb_lint.py` for rule checks + LLM gap analysis layer |
| `/kb-compile` | Skill (LLM) | 3-phase wiki compiler: scan → plan (human review) → compile |
| `/kb-merge` | Skill (LLM) | Consolidate duplicate wiki concepts, update backlinks, archive |
| `/kb-reflect` | Skill (LLM) | Cross-cutting synthesis, gap detection. Manual-only, Leo surfaces proactively |
| `kb_search.py` | Python script | TF-IDF keyword search, cached index. Called by skills internally |

### Design Decisions (2026-04-05)
- **Hybrid architecture**: Python for deterministic (search, lint rules, indexing), skills for judgment (compile, reflect, merge)
- **Human-in-the-loop compile**: Plan phase required before compilation — James reviews concept groupings before tokens are spent
- **Separate wiki domains**: `hard/wiki/` and `soft/wiki/` kept separate (can merge later; reflect reads across both)
- **TF-IDF only for search**: Semantic fallback deferred until local LLM infra is in place
- **Reflect is manual**: Leo proactively suggests but never auto-runs. Same pattern as `/consult-notebook`
- **Inspired by**: Louis Wang's `llm-knowledge-base` (louiswang524/llm-knowledge-base) — cherry-picked 5 capabilities, adapted to James's existing script-based pipeline

## Out of Scope
- Deleting `learning/` directory (James does manually after verifying)
- Claude-powered content discovery (`--discover` mode)
- Automatic cron installation
- Embedding-based semantic search (deferred to local LLM — see backlog)
- NotebookLM integration (existing notebooks stay separate)
