Anatomy of one training step

You already know the forward pass cold. This lesson teaches the other half: the four things that happen in a single training step — the part that actually changes the weights.

Why this lesson (mission tie-in): "Train one from scratch" and "debug training" both reduce to: what happens in one step, and why. Get this and nanoGPT's train.py becomes readable, the debugging recipe makes sense, and CFM/TransAct training is just this loop with a different loss.

The one idea

Training is a loop. Each pass through the loop is one step, and one step is exactly four sub-steps. The forward pass — everything you already understand about attention, heads, blocks — is only the first of the four.

1

Forward — turn inputs into a loss

Run the batch through the model to get logits (scores over the vocabulary at every position), then collapse "how wrong were we?" into a single number, the loss. This is the only sub-step you've seen so far.

2

Backward — ask every weight "how did you contribute to the loss?"

Autograd walks the computation graph in reverse and fills a gradient ∂loss/∂θ for every parameter θ. The gradient is the direction that would increase the loss fastest.

3

Update — step every weight downhill

The optimizer nudges each weight a little in the opposite direction of its gradient. After the step, the model is microscopically better at this batch.

4

Reset — clear the gradients

Gradients accumulate by default, so you zero them before the next step. Forgetting this is one of the most common training bugs (you'd be summing gradients across steps).

Sub-step 1, precisely: the loss

For next-token prediction the loss is cross-entropy. At one position, the model outputs logits → softmax turns them into a probability distribution p over the vocabulary; the loss is the negative log-probability it assigned to the actual next token:

p = softmax(logits) loss = −log p[correct token] # one position total = mean over all positions # teacher forcing: every position scored at once

Teacher forcing is why training is fast: you feed the whole true sequence in, the causal mask stops each position from cheating, and you compute the loss at every position in one forward pass.1

The sanity check that opens the debugging track. Before training, the weights are random, so the model is roughly uniform: p ≈ 1/V for vocab size V. So the initial loss should be about −log(1/V) = log V. For GPT-2's V = 50257, that's ≈ 10.82. If your untrained model doesn't start near log V, something is wrong before you've trained at all — this is the first check in Karpathy's recipe.2

Sub-steps 2–3, precisely: gradient and update

There's one beautiful result worth carrying: for softmax + cross-entropy, the gradient of the loss with respect to the logits is just

∂loss/∂logits = p − y # predicted distribution minus the one-hot truth

If the model already puts all mass on the right token, p − y = 0 → no gradient → no update. The more wrong it is, the bigger the push. Backprop chains this signal back through the unembedding, the blocks, the attention, all the way to the embeddings.

The optimizer (almost always AdamW for transformers) then updates each weight using a smoothed estimate of the gradient and its variance:

m ← β₁·m + (1−β₁)·g # running mean of the gradient v ← β₂·v + (1−β₂)·g² # running mean of its square θ ← θ − lr · m̂ / (√v̂ + ε) # (m̂, v̂ are bias-corrected)

You don't need to memorize this yet (it's Lesson 03), only to see that step 3 is where weights move, governed by the learning rate lr.

All four steps, in real code

This is the heart of nanoGPT's training loop — the whole thing is ~300 lines, but the part that is a training step is just this:3

# x: [B, T] input tokens   y: [B, T] = x shifted left by one (the targets)
for step in range(max_steps):
    x, y   = get_batch("train")            # a batch of B sequences, length T
    logits = model(x)                       # ① FORWARD → [B, T, V]
    loss   = F.cross_entropy(               # ① collapse to one number
                 logits.view(-1, logits.size(-1)),  # [B*T, V]
                 y.view(-1))                          # [B*T]  mean −log p(correct)
    opt.zero_grad(set_to_none=True)         # ④ RESET last step's grads
    loss.backward()                         # ② BACKWARD → fills every .grad
    opt.step()                              # ③ UPDATE → AdamW moves the weights

That's it. Everything else in a real trainer — data loading, mixed precision, checkpoints, evaluation, LR schedules — wraps around these four lines. Karpathy's "Let's build GPT" builds exactly this from an empty file.4

Connection to your world (recsys). Training a recommender is the same four steps — forward, loss, backward, update. Only sub-step 1's loss changes:
  • Next-item (SASRec, the FM): still cross-entropy over "next token" — but the vocabulary is the item catalog (millions). A full softmax is infeasible, so you swap in sampled softmax / in-batch negatives (Lesson 07). Forward + backward + AdamW are untouched.
  • Ranking (TransAct v2, CFM): the loss becomes BCE over engagement heads plus a future-action loss — but it's still "compute a loss, loss.backward(), opt.step()" (Lesson 08).
So when you pressure-test a CFM training choice, you're almost always reasoning about sub-step 1 (the loss / negatives) — the other three are the same machine.
