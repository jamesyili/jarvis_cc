## James's additions (2026-08-18, for the joint doc)

**Sequencing spine — the calibration critical path:**
- First question: **when can we get calibrated classifiers?** For teen safety specifically: which CQ signals matter most → calibrated versions uploaded to **Galaxy** (Pinterest feature store).
- **In parallel** (recsys side, not blocked on calibration): run experiments with uncalibrated signals, stand up experiment setup, build the scaffolding both sides align on.

**Per-lever scoping:**
- **L1 utility = density control.** P0 = density control on one CQ signal; P1 = multi-signal density control + spacing for multiple signals.
- **SSD (sliding spectrum decomposition)** = the diversification mechanism; second most promising lever in James's read. **Verified against the KDD'21 paper (Leo, 8/18):** SSD's greedy selection maximizes `Σ relevance + γ·diversity`, where diversity = volume of the hyper-parallelepiped spanned by the **item vectors**, computed via one-step **modified Gram-Schmidt** orthogonalization over sliding windows stacked into a trajectory tensor (the "spectrum" in the name = singular-spectrum analysis of that tensor, *not* a score spectrum). Native inputs = per-item scalar quality score + per-item **embedding**; the mechanism is vector-agnostic, so feeding a **classifier prediction vector** as the item vector (the Pinterest adaptation) is sound — in that configuration it does consume the full score profile, threshold-free. **Design caution for the doc:** the diversity term *de-clusters* similar score-profiles; it does not *prefer* low-risk ones — suppression must come from the quality term or density control. Spacing = de-clustering only.
- **Corpus selection: NOT useful for teen safety** — applied universally, no cohort-specific treatment. ⚠️ Revises the doctrine's §4.1 emphasis for *this* program: corpus stays relevant only for universal worst-of-the-worst.
- **Probabilistic throttling** = new build; if pursued, at retrieval or L1. Time-to-implement trade-off: it's *either* throttling *or* density control on the timeline.
- **Model training path (CLARIFIED by James, 8/18 grill):** the Dhruvil + Dafang paper assignment is **NOT** reweighting — it is the **quality head plan**, where the head predicts **downstream density**: a session crowded with unsafe/GenAI content gets labeled an unsafe session, and the head predicts that session-level outcome on **downstream-rewards machinery**. Explicitly *not* per-pin label prediction. This is the doctrine's §5.2 trajectory head with a concrete, cheaper target — session density is computable from *existing logged classifier scores* (no LLM judge needed for v0), which decouples the training-time path from the judge-calibration critical path. James: "that's where I want to push the group."
